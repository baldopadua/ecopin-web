# EcoPin Web - Field Crew Role & Feature Specification

## 1. Executive Summary & Context

This document provides a comprehensive technical specification for implementing the **Field Crew** role within the `ecopin-web` application. The specification is derived directly from system architecture wireframes and operational workflows.

The **Field Crew** role represents on-the-ground environmental and sanitation management personnel responsible for executing cleanup operations, logging before-and-after evidence, tracking assigned task clusters, and managing route navigation.

---

## 2. Global Role Rules & Navigation Structure

### 2.1 Role & Permissions Baseline
* **Role Identifier**: `FIELD_CREW`
* **Access Scope**:
  * **Global Operations Visibility**: Field Crew members can view all global cleanup tasks and operations created by Officers.
  * **Edit/Modification Restrictions**: Editing, uploading evidence, and marking tasks complete are strictly scoped to cleanup tasks **assigned** to the authenticated crew.
  * **Report Integrity**: Report metadata (title, citizen description, issue type, coordinates) is **read-only** for Field Crew members to maintain data integrity.

### 2.2 Navigation Map & Routing

| Module / Screen Name | Route Path | Core Function |
| :--- | :--- | :--- |
| **My Route** | `/my-route` | Real-time map navigation & active route tracking |
| **Command Center / Dashboard** | `/dashboard` | Daily objective metrics, pending task queue, quick start actions |
| **Map Grid** | `/map-grid` | Filtered map grid of officer-assigned cleanup clusters |
| **Operations / Cleanup Tasks** | `/operations` | Master list of cleanup tasks with pagination & search |
| **Raw Data** | `/raw-data` | Master list of individual approved incident reports |
| **Account & Profile** | `/profile` | User profile, security settings, theme, & session management |
| **Task Details View** | `/operations/:cleanup_task_id` | Cluster overview, report table, before/after gallery, completion trigger |
| **Report Details View** | `/operations/:cleanup_task_id/:report_id` | Individual report evidence upload, LGU notes, activity log, route link |

## 3. View-by-View Detailed Specifications

---

### Module 1: My Route (`/my-route`)

#### Purpose
Provides real-time GPS tracking and visual navigation pathways to assigned cleanup locations for active crew shifts.

#### Key Features & Requirements
* **Active Task Mapping**: Displays all current tasks and incident report clusters assigned specifically to the logged-in crew.
* **Live Route Pathing**: Render live tracking paths and direction vectors linking the crew's current location to assigned objectives (similar to turn-by-turn navigation interfaces like Google Maps).
* **Cluster Visualizers**: Visual markers indicating clustered reports on the active route map.

---

### Module 2: Command Center / Dashboard (`/dashboard`)

#### Purpose
Operational home screen serving as the daily dispatcher interface for Field Crew members.

#### Key Features & Requirements
* **Objective Summary Widget**: Displays the current primary objective for the shift.
* **Metrics Tracker**:
  * Total Completed Tasks vs. Total Pending Tasks count.
  * Visual progress indicator.
* **Upcoming Tasks Queue**: List view of queued tasks scheduled for completion.
* **Quick Actions**:
  * `Start Task` button for the current active objective.
  * `View Live Map` toggle to visualize the objective directly on the map interface.

---

### Module 3: Map Grid (`/map-grid`)

#### Purpose
A filtered spatial overview of approved pinned incident reports integrated into active cleanup tasks.

#### Key Features & Requirements
* **Filtered Spatial Display**:
  * Displays approved pinned reports and clusters **only** if included in cleanup tasks generated by Officers.
  * **Constraint**: Excludes unassigned raw citizen reports to prevent map clutter and operational confusion.
* **Precision Filtering**: Interactive filter controls to refine map views by date, priority, or task status.
* **Interactive Pins**:
  * Clicking a pinned report displays a quick summary and provides a direct navigation link to `/operations/#cleanup-task-id/#report-id`.

---

### Module 4: Operations / Cleanup Tasks (`/operations`)

#### Purpose
Global list interface for exploring, searching, and managing officer-created cleanup task clusters.

#### Key Features & Requirements
* **Global Operations Listing**: Displays all cleanup tasks created by Officers across the system.
* **Permission Enforcement**:
  * Crew can inspect all global operations.
  * Modification actions are disabled for tasks not explicitly assigned to the viewing crew.
* **Search & Filter Suite**:
  * Keyword search by task title or location.
  * Multi-attribute filter options with a single-click `Reset Filters` control.
* **Pagination & Counts**:
  * Displays current total item count and paginated navigation.

---

### Module 5: Raw Data List (`/raw-data`)

#### Purpose
Tabular data view of individual approved incident reports bundled inside cleanup operations.

#### Key Features & Requirements
* **Approved Report Repository**: Lists all approved individual reports generated manually or automatically by Officers within assigned tasks.
* **Direct Report Navigation**: Clicking any report row navigates directly to `/operations/#cleanup-task-id/#report-id`.
* **Crew Field Modification**: Field Crew can edit designated fields (e.g., crew notes or evidence uploads) if assigned to the task.
* **Pagination**: Standard table pagination with page size and total record counters.

---

### Module 6: Account & Profile Settings (`/profile`)

#### Purpose
User profile management, credential validation, UI theme toggle, and session termination.

#### Key Features & Requirements
* **Avatar & Initial Fallback**:
  * Displays uploaded profile image.
  * Defaults to the user's initials if no profile picture is set.
* **Inline Full Name Editor**:
  * Displayed as static text with an adjacent edit icon.
  * Clicking the edit icon transforms text into an inline editable input field with an adjacent `Save` button.
  * Saving automatically updates the profile state and reverts the input back to plain text without requiring a global page submit button.
* **Password Change Modal / Section**:
  * Requires verification of `Old Password`.
  * Enforces password strength constraint validation on `New Password` and `Re-enter Password`.
* **Appearance Preferences**:
  * Option to toggle between `Light Mode`, `Dark Mode`, or `System Default` appearance settings.
* **Logout Workflow**:
  * Logout trigger prompts a confirmation modal ("Are you sure you want to log out?") prior to invalidating session tokens.

---

### Module 7: Cleanup Task Detail View (`/operations/:cleanup_task_id`)

#### Purpose
The centralized management view for a specific task cluster, aggregating bundled reports, evidence galleries, and completion triggers.

#### Key Features & Requirements

#### 7.1 Report Table
* Displays bundled reports inside the task with columns:
  * `Title`
  * `Issue Type`
  * `Status`
  * `Lifecycle Stage`
  * `Validation Status`
  * `Actions` (View Details button)

#### 7.2 Evidence & Map Overview
* **Before & After Gallery**: Aggregates all Before and After proof photos from all reports contained within the cleanup task.
* **Static Location Map**: Displays the boundary/location overview of the cleanup task.

#### 7.3 Task Metadata & Completion Logic
* **Task Summary**: Displays Title, Full Description, Current Task Status, Assigned Crew Members, and Cluster Progress Bar.
* **Progress Bar**: Reflects cluster completeness percentage based on handled reports.
* **`Mark Task Complete` Trigger**:
  * Button is enabled **only** when all bundled reports within the cleanup task have reached a terminal or acknowledged state.
  * **Business Rule**: Reports do not all require physical field remediation; reports categorized as "Acknowledge Only" count toward completion once acknowledged.

---

### Module 8: Individual Report Detail View (`/operations/:cleanup_task_id/:report_id`)

#### Purpose
Detailed evidence logging, incident inspection, and field remarking interface for a single report inside a cleanup task.

#### Key Features & Requirements

#### 8.1 Read-Only Incident Metadata
* **Header & Lifecycle**: Report Title, Description, Lifecycle Stage, and Current Status (Read-Only).
* **Incident Attributes**: Issue Type, Severity Level, Geolocation Coordinates, Street Name, Landmark, Location Name, Submission Date, and Last Updated Timestamp.
* **Reporter Information**: Submitter's Name and User ID (displayed only if citizen opted to disclose identity).

#### 8.2 Photo Verification System (SWMO Field Crew Proof)
* **Citizen Evidence**: View read-only photos submitted during citizen report creation.
* **SWMO Before & After Photo Upload**:
  * Field Crew can upload proof photos under `Before Photo` and `After Photo` categories.
  * **Constraints**:
    * Maximum of **5 photos** total per report.
    * File size limit enforced per image (MB restriction).
    * Delete/remove capability for crew-uploaded photos.

#### 8.3 Field Crew Notes & Logs
* **LGU Notes**: Dedicated text field where field crew members add operational remarks or field observations.
* **Report Activity Log**: Displays report-specific audit trail (e.g., "Lifecycle Stage Update", action timestamps, and modification details).

#### 8.4 Contextual Indicators & Actions
* **Static Location Map**: Pinpoint map display for the specific report.
* **Cleanup Task Context**: Displays parent task title, description, status, assigned crews, and overall cluster progress bar.
* **Navigation Buttons**:
  * `Back Button`: Returns user to the parent Operations page.
  * `View on Map`: Action button that redirects the crew directly to the `My Route` navigation view (instead of the standard Map Grid) centered on this report's location.

---

## 4. Technical Integration & Data Constraints

| Attribute | Constraint / Rule |
| :--- | :--- |
| **Max Evidence Uploads** | 5 photos max per report (Before/After combined) |
| **Image Size Limit** | Enforce MB threshold validation on client & server |
| **Inline Auto-Save** | Profile name changes execute immediate API updates on save trigger |
| **Task Completion Gate** | `Mark Task Complete` button remains disabled until `completed_reports == total_reports` |
| **Map Navigation Target** | "View on Map" inside report details routes to `/my-route` with targeted report focus |
